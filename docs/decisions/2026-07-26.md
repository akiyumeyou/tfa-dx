# 技術決定ログ 2026-07-26

TFA-DX LP の初期構築時に行った決定。

---

## 1. Next.js 16（App Router）+ Tailwind CSS v4 + TypeScript を採用

**なぜ**
デプロイ先がVercel前提のため、ゼロ設定で本番デプロイでき、後からページ追加や
フォーム連携（Route Handler / Server Actions）にそのまま拡張できる構成を選んだ。

**却下した選択肢**
- 素のHTML/CSS/JS：1ページ完結なら十分だが、3ページ構成で共通ヘッダー・フッター・
  データを持つため、コンポーネント化できないと同じ文言の修正漏れが起きる
- Astro：静的LPとしては最速だが、Vercel + Next.js の方が今後の申込フォーム実装や
  データ取得への拡張時に情報量が多く、詰まりにくい

**注意点**
`create-next-app` が生成した `AGENTS.md` に「Next.js 16 は破壊的変更がある。
`node_modules/next/dist/docs/` を読め」と書かれている。今回参照した範囲では
`next/font/google`・Metadata API・`next/link` は従来通りの書き方で動作した。

## 2. コンテンツを `src/data/` に集約する

**なぜ**
日程・講師名・肩書は本番までに変更される可能性が高い。JSXに直接書くと同じ情報が
トップページとプログラム詳細ページの2箇所に散り、片方だけ古くなる。
`sessions` 配列を単一の情報源にして、トップのタイムラインと `/program` の詳細カードの
両方が同じデータを読む構成にした。

**構成**
| ファイル | 持つもの |
| --- | --- |
| `src/data/site.ts` | サイト名・キャッチコピー・主催者情報・開催概要・申込URL |
| `src/data/program.ts` | 全6回の日程/講師/目標、5つの特徴、対象者、Q&A |
| `src/data/people.ts` | 講師5名・メンター4名のプロフィール |

**申込URLの扱い**
フォームURLが未定のため `site.ts` の `links` に `#apply` / `#briefing` を仮置きした。
確定時にこの2行を書き換えるだけで、全ページ・全CTAが切り替わる。

## 3. CTAボタンをアクセント色の背景 + 濃紺文字にした（チラシと配色が異なる）

**なぜ**
デザイン指示は「Accent `#E8A87C` をCTAに使う」かつ「コントラスト比 4.5:1 以上（WCAG AA）」
だったが、この2つは白文字では両立しない。

| 配色 | コントラスト比 | 判定 |
| --- | --- | --- |
| `#E8A87C` 背景 + 白文字 | 1.9:1 | 不合格 |
| `#E8A87C` 背景 + `#2D2D3F` 文字 | 6.6:1 | 合格 |
| `#A35526` 背景 + 白文字 | 5.4:1 | 合格だが色が茶色に寄る |

チラシの色をそのまま維持できる「アクセント色 + 濃紺文字」を採用した。
高齢者ユーザーを想定するPOTZの文脈とも合う。

**補足**
白背景の上に置くアクセント色の**文字**（`/program` の「A.」など）は `#E8A87C` では
薄すぎるため、別トークン `--color-accent-strong: #A35526`（対白 5.4:1）を用意した。

## 4. FAQアコーディオンを `<details>` / `<summary>` で実装

**なぜ**
JavaScriptなしで開閉・キーボード操作・スクリーンリーダー対応が標準で効く。
Reactのstateで実装すると、同じ挙動をアクセシビリティ属性込みで自前実装することになり、
コード量が増えるうえに壊れやすい。Server Componentのままにできる利点もある。

**却下した選択肢**
`useState` + `aria-expanded` によるクライアントコンポーネント実装。
アニメーションを細かく制御したくなった時点で再検討する。

---

## 5. 人物写真をビルド時のファイル存在チェックで出し分ける

**なぜ**
写真は後日差し替え前提だが、「あとで `photo: null` を書き換える」方式だと
画像を置いた人がコードも触る必要がある。`src/lib/photo.ts` の `resolvePhoto()` で
`public/images/` 配下を `fs.existsSync` で探し、無ければイニシャル円にフォールバックする。

静的生成（SSG）なのでこの判定はビルド時に1回だけ走り、実行時コストはない。
画像を置いて再デプロイするだけで反映される。

**対応拡張子**: `.jpg` / `.jpeg` / `.png` / `.webp`

## 6. ヒーロー右カラムに事前説明会カードを置いた

**なぜ**
デスクトップ幅でヒーロー右half が空く。かつコンバージョン設計上
「まずは説明会だけでも」の導線を最上部に置きたかった。
`public/images/hero.*` を置くとカードの上に写真が入る。

当初ヒーロー本文側に置いていた「事前説明会を見る」ボタンは、このカードと重複するため削除した。

## 7. `Noto_Sans_JP` を `preload: false` で読み込む

**なぜ**
日本語フォントはunicode-rangeで多数のファイルに分割される。全件をpreloadすると
初期表示で大量のリクエストが走り、かえって遅くなる。`display: "swap"` と併用。
