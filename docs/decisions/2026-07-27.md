# 技術決定ログ 2026-07-27

## 1. 講師・メンター写真は「元写真 → 生成」の2段構えにする

**何を決めたか**

- 元写真は `assets/people/<instructors|mentors>/<photoBase>.<ext>`（public外）に置く
- `npm run images`（`scripts/build-people-images.mjs` / sharp）で
  `public/images/<...>.webp` に **正方形 800×800px・quality 82** で生成する
- `public/images/` の写真は生成物。手で置き換えない

**なぜ**

受け取った9枚は 504×465 〜 2048×2048、縦横比も 3:2 / 1:1 / 縦長とバラバラだった。
円形アバターで横に並べるため、表示側の `object-cover` 任せにすると人によって
顔の大きさ・切れ方が揃わない。公開前に正方形へ揃えてしまう方が確実。

800pxにしたのは、最大表示112pxの円 × 3倍解像度でも足りて、将来大きく使っても耐えるため。
これ以上大きくしても next/image が配信するのは 128px / 256px なので意味がない
（実配信サイズは 6KB 程度）。元写真をリポジトリに残すのは、切り出しをやり直せるようにするため。

**却下した選択肢**

- 元写真をそのまま `public/` に置いて CSS の `object-position` で調整：
  人ごとに調整値をコンポーネント側に持つことになり、写真差し替え時に必ず崩れる
- 手作業でトリミング：再現性がなく、写真が増えるたびに同じ作業が発生する

## 2. トリミングは「顔の位置」を指定して切り出す

**何を決めたか**

単純な中央切り抜きではなく、写真ごとに顔の中心 `x, y` と寄り `zoom` を
`FOCUS` テーブルに持ち、顔がフレームの上から38%の位置に来るように正方形を切り出す。
はみ出す場合は画像内に収まるようクランプする。

**なぜ**

中央切り抜きだと、全身に近い写真（淵上さん・國本さん）は顔が小さく写り、
縦長の写真（佐藤さん）は頭が切れる。実際に9枚を並べて確認し、顔の大きさが
揃うまで `zoom` を調整した。顔を中央ではなく上寄り（38%）に置くのは、
人物写真として自然に見え、円形マスクでも顎が切れないため。

**注意点**

写真を差し替えたら `FOCUS` の値も見直す。指定がない写真は
`DEFAULT_FOCUS`（中央・やや上寄り・寄りなし）で処理される。

## 3. イメージ画像3枚の配置先

**何を決めたか**

| 元画像（`assets/site/`） | 内容 | 配置先 |
| --- | --- | --- |
| `hero.png` | AIアイコンと学習中の女性（3:2） | トップページ ヒーロー右カラム |
| `online-lesson.png` | オンラインで受講している様子（3:2） | トップページ「全6回の流れ」下の説明ブロック |
| `eyecatch.png` | 横長バナー（2.89:1） | プログラム詳細ページ上部の全幅バナー ＋ OGP（1200×630に切り出し） |

生成物は `public/images/` 配下（人物写真と同じ `npm run images` で出力）。

**なぜ**

- ヒーロー右カラムは元々 `hero.*` を置くと写真が入る作りだったので、学習イメージをそこに入れた。
  ただし旧コードは 800×1000（4:5）指定で、3:2の写真だと左右が大きく切れるため実寸に合わせた
- 横長バナーは幅の狭いカラムに入れると細くなるだけなので、全幅で使えるページ上部と
  OGP（1200×630）に回した。トップに置くと見出しが押し下がるうえ、ヒーロー右の写真と
  同系統の絵が縦に2枚並んで冗長になる
- OGPは png（1MB超）ではなく jpg（52KB）で出力。写真主体でクローラの取得も速い方がよい

**注意点**

トップに大きなメインビジュアルを置く構成に変えたくなったら、`eyecatch.webp` を
そのままトップのヒーロー上に移せる（生成物は全幅1600pxで出している）。

## 4. ファビコンは Next.js のファイル規約で置き、`npm run images` から生成する

**何を決めたか**

`assets/site/icon.png`（ロゴマーク 576×576・透過）を元に、
`src/app/favicon.ico`（16/32/48px）・`src/app/icon.png`（256px・透過）・
`src/app/apple-icon.png`（180px・白背景）を生成する。

**なぜ**

- Next.js 16 は `app/favicon.ico` `app/icon.*` `app/apple-icon.*` を見て `<link rel="icon">` を
  自動生成する（`node_modules/next/dist/docs/.../metadata/app-icons.md`）。
  `metadata.icons` を手書きするより配置ミスが起きない
- `.ico` を残したのは、`/favicon.ico` を直接取りに来る古いブラウザやクローラがいるため。
  sharp は ico を書き出せないので、PNGを格納できるICOの仕様に沿ってヘッダを組み立てている
- apple-icon だけ白背景で `flatten` するのは、iOSが透過部分を黒く塗るため
- PNGはパレット化して軽量化（256px: 122KB → 35KB）。小さく表示される画像なので劣化は見えない

**注意点**

元のロゴは細い線と文字を含むため、16〜32pxでは紫の円としか判別できない。
タブでの視認性を上げたい場合は、中央のモチーフだけを切り出した小サイズ用の画像を
別に用意して `icon1.png` / `icon2.png` として置く（Next.jsが番号順に複数出力する）。

## 5. 講師・メンターは「長方形カード」で見せる

**何を決めたか**

- 写真は円形アバターをやめ、縦長4:5（720×900px）に統一
- 講師ページは1枚ずつの横長カード（写真左・テキスト右）、メンターは2列のカード
- プロフィール文と肩書は企画書「登壇者・伴走メンター」ページの内容に差し替え
- `Person.title`（1行）→ `titles: string[]`（複数行）、`tokushimaBased` を追加
- `Avatar.tsx` は `PersonPhoto.tsx` にリネーム（円形前提の名前をやめた）

**なぜ**

円形＋112pxでは、せっかくの顔写真がほぼ潰れていた。企画書の紹介文は1人200字前後あり、
写真とテキストを横に並べるカードのほうが読みやすく、企画書のレイアウトとも一致する。
肩書は2行のケース（國本さん・佐藤さん）があるため配列で持つことにした。

**注意点**

写真の切り出し比率は `scripts/build-images.mjs` の `PORTRAIT_ASPECT` 一箇所で決まる。
表示側（`PersonPhoto`）の `aspect-[4/5]` と必ず揃えること。

## 6. トップの講師紹介は「自動で流れるカード」＋ポップアップ

**何を決めたか**

トップページに登壇者5名・メンター4名の横流しカードを2列（逆方向）で置き、
カードをクリックするとその場でプロフィールのポップアップを開く。

- CSSアニメーション（`globals.css` の `.marquee-track`）で `translateX(0 → -50%)`
- ホバー・タッチ中・ポップアップ表示中は停止。`prefers-reduced-motion` では動かさない
- 横スクロールも効くので、流れを待たずに指で送れる

**なぜ**

- 「参考サイトのように横に流れる」という要望。JSライブラリを足さずCSSだけで足りる
- 1周ぶんの並びが画面幅より短いと流れている途中で空白が見えるため、
  `MIN_LOOP_WIDTH`(2600px) を超えるまで並びを繰り返してから2周ぶん並べている
- 写真パスの解決（`lib/photo.ts`）は fs を使うのでサーバー側で済ませ、
  `PersonCard` に詰め替えてからクライアントコンポーネントへ渡している
- カード幅は画面幅に応じて 260→360px（`CARD_WIDTH_CLASS`）。広い画面で横に4人前後が収まる大きさにしている。
  幅を変えたら流れる速さ（`secondsPerPerson`）も見直す（1周の秒数 ＝ カード枚数 × この値）

**何を決めたか**

## 8. 写真の高さが揃わないのは flex の stretch が原因だった

**何を決めたか**

`PersonPhoto` の枠に `self-start` を付ける。

**なぜ**

写真は 4:5（720×900）で生成しているのに、講師カード上では人によって縦横比が違って見えていた。
原因は `flex flex-row` の中で `align-items: stretch` が効き、写真の高さがカードの高さ
（＝紹介文の長さ）まで引き伸ばされていたこと。高さが確定してしまうと `aspect-[4/5]` は無視され、
`object-cover` が人ごとに違う切り取り方をする。`self-start` で高さを内容基準に戻すと解決する。

元画像の切り出しは問題なかった（撮り直し・再アップロードは不要）。
あわせて顔の大きさを揃えるため `FOCUS` の zoom を微調整した（淵上・國本・佐藤・西村）。

**注意点**

`aspect-*` を使う画像を flex/grid の子に置くときは、常に `self-start`（または `items-start`）を
セットで書く。これがないと同じ症状が再発する。

## 9. 申込フォームのQRコードは「リンクと必ずセットで」差し替える

**何を決めたか**

`links.apply` / `links.briefing` と `assets/site/qr-*.png` は同じ宛先を指す前提で運用する。
外部リンク（`http` で始まるURL）は `CtaButton` が自動で別タブ表示にする。

**なぜ**

QRとボタンで別のフォームに飛ぶ事故は、公開後に気づきにくく影響が大きい。
今回はQRを実際にデコードして短縮URLの転送先と一致することを確認した
（リサイズ後の生成画像も再デコードして読み取れることを確認済み。
QRは拡大時ににじむと読めなくなるため、`sharpEdges: true` で nearest 補間にしている）。

## 10. スマホのメニューは「アイコン＋メニューの文字」で出す

**何を決めたか**

1024px未満ではヘッダーにハンバーガーボタンを出し、押すと3項目のパネルが開く。
アイコンだけにせず「メニュー」の文字を必ず添える。項目の高さは56px。

**なぜ**

それまでスマホでは申込ボタンしか出ておらず、プログラム詳細・講師紹介へ行く導線が無かった。
文字を添えるのは、ハンバーガーアイコンに馴染みのない利用者を想定しているため（POTZの方針）。
開閉状態は `useState` にパスを持たせて `openedPath === pathname` で判定している
（`useEffect` で閉じるとReactの lint に引っかかるため）。

## 11. トップページのアイキャッチは「画像の見出し＋金色だけ光らせる」

**何を決めたか**

- 帯は 2.5:1（1600×640）。`focusY: 0.15` で上寄りに切り出し、頭が切れないようにする
- 見出しは画像（`hero-title.webp`）を帯の左に重ね、`<h1>` には読み上げ・検索用の文字を隠して置く
- 「輝く」の金色部分だけを光らせるため、元画像から金色の画素を判別したマスクを生成し、
  そのマスクで切り抜いた層に白い光の帯を流す（`.gold-shine`）

**なぜ**

- 文字を画像にすることで、フォントでは出せない書体・金の質感をそのまま使える。
  ただし検索エンジンと読み上げには文字が必要なので `sr-only` のテキストを併記した
- 光らせる範囲を手作業で切り抜くと、見出し画像を作り直すたびに作業が発生する。
  色で自動判別すれば `npm run images` だけで済む
- ヒーロー側にあった同じ文言の見出しは削除した（同じコピーが縦に2回出るため）

**注意点**

`prefers-reduced-motion` では光らせない。金色以外を光らせたい場合は `isGold` を調整する。
