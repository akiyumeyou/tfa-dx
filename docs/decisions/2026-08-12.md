# 技術決定ログ 2026-08-12

## 1. Google検索向けのSEO設定を Next.js のファイル規約で持つ

**何を決めたか**

- `src/app/sitemap.ts` / `src/app/robots.ts`（App Router のメタデータ規約）で
  `sitemap.xml` と `robots.txt` を生成する。URLは `site.url` から組み立てる
- 3ページすべてに `alternates.canonical` を入れる
- 構造化データ（JSON-LD）は `src/lib/structured-data.ts` に集約し、
  `src/components/JsonLd.tsx` から `<script type="application/ld+json">` として出力する
  - layout: `EducationalOrganization` / `WebSite`
  - トップページ: `Course`（`CourseInstance` 込み） / `FAQPage`
- `robots` メタに `googleBot.max-image-preview: large` を追加
- Search Console の所有権確認コードは環境変数
  `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` から `metadata.verification.google` に流す

**なぜ**

公開済みの `https://tfa-dx.vercel.app` に `/robots.txt` と `/sitemap.xml` が存在せず
（404）、Googleがサイト全体の構造を把握する手がかりがなかった。OGP・title・description は
既に整っていたので、不足していたのは「クロール導線」と「機械可読な内容説明」の2点だけ。

JSON-LD の内容を `src/data/` から導出しているのは、日程・講師・締切を直書きすると
`program.ts` / `people.ts` を直したときに構造化データだけ古いまま残るため。
`hasCourseInstance` の日付は `sessions` の第1回〜第6回から自動で拾う（中間交流会は除外）。

`courseMode` を `Online` ではなく `Blended` にしたのは、第6回のみ会場開催のため。

**却下した選択肢**

- `public/sitemap.xml` を手書きする → URL変更・ページ追加のたびに更新漏れが起きる
- `schema-dts` を入れて型付けする → 依存を1つ増やすほどの規模ではない。
  検証は Rich Results Test で足りる
- 確認コードをコードに直書きする → 環境変数にしておけば、独自ドメイン移行時に
  プロパティを取り直してもコード変更が要らない

## 2. 「TFADX」は独自ワードではないので、年度で差別化する

**調査でわかったこと**

「TFADX」で検索したときの競合は2種類ある。

同名事業の過去年度・関連サイト（すべて当サイトより先にインデックス済み）:

| サイト | 状態 | 備考 |
| --- | --- | --- |
| https://tfa.life/ | 稼働中 | 「只今 TFA 2026 開催概要ページを更新中です」と表示。TFA本体 |
| https://mirea.hp.peraichi.com/tfadx | 稼働中 | **URLに `/tfadx` を含む**。ペライチ製 |
| https://awa-onna.com/tfa/ | 稼働中 | NPO法人GWEI |
| https://www.pref.tokushima.lg.jp/.../5052423/ | 稼働中 | 徳島県公式・令和3年度。**ドメイン権威が非常に高い** |
| https://dx-tfa.net/ | **DNS解決せず** | 消滅済みだがGoogleのインデックスには残存 |

さらに、英語圏では **TFADX が米国投資信託のティッカーシンボル**
（TFA Multidimensional Tactical Fund Class I）として使われており、
Morningstar・Stock Events などの高権威サイトが「TFADX ... 2026」を含むページを持つ。

**何を決めたか**

「TFADX」単体で勝ちにいくのではなく、**年度で一意にする**方針をとる。

- `site.shortName` を `TFA-DX` → `TFADX` に変更（連絡先 tfadx2026@gmail.com に合わせた）
- `site.edition` = `2026年度` / `site.editionJp` = `令和8年度` を追加
- title を `とくしまフューチャーアカデミーDX（TFADX）2026年度 | …` に変更。
  下層ページのテンプレートも `%s | …（TFADX）2026年度` に統一
- 表示テキストにも3か所だけ自然に入れた（ヘッダーの英字ライン・h1のsr-only・フッターの事業名）。
  過剰に埋め込むとスパム判定されるため、これ以上増やさない
- 構造化データの `alternateName` に表記ゆれ（TFADX / TFA-DX / TFA DX / 英語表記）をまとめた

**なぜ年度なのか**

毎年開催の事業なので、Googleから見ると「同じ名前のページが複数年ぶんある」状態になる。
年度を書いていないページは、どの年のものか判断できず古いページに負ける。
逆に年度を明示すれば「TFADX 2026」という検索意図に対して当サイトが最も適合する。

**却下した選択肢**

- キーワードを本文に大量に散らす → スパム判定リスク。固有名詞では効果より害が大きい
- 過去年度サイトへの言及・比較を載せる → 主催者側の調整事項であり、サイト側で扱う話ではない

## 3. 検索順位の主因はコードではなく被リンクとドメイン

`tfa-dx.vercel.app` は2026年7月に作られた新規サブドメインで、被リンクがゼロに近い。
一方の競合は数年ぶんの実績があり、うち1つは `pref.tokushima.lg.jp`（自治体ドメイン）。

**この差はコード側では埋められない。** 効果が大きい順に、主催者・受託者側の対応が要る。

1. 徳島県の公式サイト（`pref.tokushima.lg.jp`）の令和8年度募集ページから当サイトへリンクしてもらう
   — 主催が徳島県なので最も現実的かつ効果が大きい
2. `tfa.life`（TFA本体）の2026年度ページから DXコースとしてリンクしてもらう
3. 独自ドメイン（例 `tfadx.jp` / `tfadx2026.jp`）を取得して Vercel に設定する
   — `vercel.app` サブドメインは評価が乗りにくい。取得する場合は**公開直後が望ましい**
   （後から移すとインデックスがやり直しになる）

## 4. Search Console 登録はユーザー操作が必要なので自動化しない

Search Console のプロパティ作成とサイトマップ送信はGoogleアカウントでのログインが要るため、
コード側は「確認コードを受け取れる口」だけ用意して手順を `docs/deploy-checklist.md` に書いた。
